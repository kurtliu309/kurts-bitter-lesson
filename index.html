Kurt's Bitter Lesson

One person, two model vendors, six versions of a dispatch rule — and how a carefully engineered pipeline got cut back to one script and one sentence: if DeepSeek can do it, give it to DeepSeek.

Kurt × Claude (Opus / Haiku) × DeepSeek (Flash / Pro) · data as of 2026-11-12
Abstract1 Background2 Six iterations3 Experiments4 Forgotten three times5 The lesson6 LimitationsAppendix

Abstract. The goal was simple: make the expensive model (Claude Opus) do less and the cheap one (DeepSeek) do more. Within a single day the dispatch rule, a Claude Code skill called delegate-coding, went from v0.3 to v2.1. Along the way it gained quota-based tier switching, code summarizers, spec writers, first-pass reviews, final reviews, gates, a ledger, sandbox copies and multi-round rework — and then lost almost all of them. The measurements say: every extra machine check adds another place where checks contradict each other. Only three things earned their keep: give the executor its full toolset, impose one hard turn limit, and have a strong model do one independent review. The final version is 14% of the peak code size, and it finished on the first try the task that deadlocked v1.0. Also: one key fact (--bare makes subagents disappear) was written down twice and still got re-learned a third time.

1Background: a plain question

Kurt does engineering work in the Claude Code desktop app. Opus is excellent but quota-limited. DeepSeek exposes an Anthropic-compatible API, so the very same Claude Code CLI can be driven by DeepSeek at almost no cost to the Claude quota. The question becomes: which work should the Claude in the main chat hand to DeepSeek, how should it hand it over, and how should the result be checked?

The answer lives in a skill file (delegate-coding/SKILL.md) that must be loaded at the start of every engineering conversation. This report follows six major rewrites of that file and the measurements behind each one.

4Forgotten three times

If you remember one part of this report, make it this timeline rather than any chart.

Nov 9 · probe
Seven tools explicitly allowed (Agent included); DeepSeek could see only three: Bash, Edit, Read. The report noted “sees 3 of 7” and never explained it.
Nov 12, morning · T0
Root cause found: --bare mode exposes only three tools, and it also passes CLAUDE_CODE_SIMPLE=1 down to child processes. Without --bare, subagents spawn and genuinely run on DeepSeek. Written into two separate notes.
Nov 12, midday · v2.0.0
During the big simplification, the new script put --bare right back, and SKILL.md dutifully recorded “cannot spawn subagents” — turning a fixable limitation into an accepted fact. One of the notes even said “keep using --bare for normal tasks”.
Nov 12, afternoon · v2.1.0 attempts 1–2
Kurt asked: “why still no subagents?” First, Agent was added to the allow list — no effect. Then the tools were listed explicitly with --tools — still nothing; even Glob and Grep went missing.
Nov 12, afternoon · v2.1.0
Dropped --bare; isolation now comes from a dedicated config directory plus --strict-mcp-config. Subagents work. Along the way we found that “read-only” mode couldn't actually stop writes (acceptEdits auto-approves them) and fixed that too.

The answer was already in T0, and it had been written down twice. But the conversation that produced v2.0.0 never read those notes; the new script was edited from the old one, and the old one carried --bare. A written lesson only counts when someone reads it. What actually preserves it is putting it inside something that gets executed — so v2.1.0 records the reason as a code comment directly above that line.

5The lesson

Hand-built process machinery layered on top of AI agents loses, in the long run, to: the full toolset, one hard limit, and one independent review by a strong model.

Rich Sutton's The Bitter Lesson argues that general methods which leverage computation eventually beat methods that encode human knowledge by hand. We walked through a miniature version of that in a single day. Click each point to see the evidence.

    6Limitations

    • Tiny samples: T4 is one task, T5 is three tasks × two runs, T6 was never scored. Any claim like “Flash beats Pro” or “an Opus spec is cheaper” is provisional.
    • Everything ran on one Windows machine, on one day, for one person. Concurrency, long tasks and timeout watchdogs were never tested.
    • Claude quota is reported only as whole percentages, so the cost of a single Opus call is invisible; there is no reliable “Claude quota saved” number.
    • The gate's real-world catch rate and false-alarm rate were never measured — it was deleted before anyone got to it.
    • Without --bare, DeepSeek now reads the project's own CLAUDE.md / AGENTS.md. We treat that as a feature, but its long-term effect hasn't been observed.

    Appendix The current rule (v2.1.0)

    SituationWhat happens
    Main chat runs Opus (“stable” tier)If DeepSeek can do it, give it to DeepSeek. Opus keeps only one- or two-step chores, work that needs MCP / browser / artifacts, and design decisions that need back-and-forth with Kurt. Opus reviews DeepSeek's diff and test output.
    Main chat runs Haiku (“economy” tier)Chat only. Engineering requests are copied verbatim into a task file, dispatched with one command, and the reply is relayed unchanged.
    Dispatch scriptOne PowerShell script: strips inherited Claude environment variables, points the CLI at DeepSeek, uses its own config directory, caps at 80 turns, prints the final reply.
    Permissionsdev: all base tools + subagents; network, push, recursive delete etc. denied. strict: read-only + subagents, Edit/Write explicitly denied.
    StoppingOnly --max-turns. Never “the model says it's done”.

    Removed along the way: quota-based tier switching, Flash code summaries, spec writers, Flash first-pass review, short-lived Opus supervisors, gates (GATE-ACCEPT / GATE-ALLOW), the ledger, sandbox copies, multi-round rework, card-writing step, templates, 30 unit tests, and the Haiku relay layer.
